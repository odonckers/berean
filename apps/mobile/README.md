# Berean mobile

Expo (SDK 58) app for Berean using a development build (`expo-dev-client`, not Expo Go). It uses Expo Router with native tabs (Read, Studyspace, Notes, Library), each tab has its own native stack, and the new architecture is on. On Android a docked search bar above the navigation bar opens a placeholder search screen. The screens show plain placeholder text for now. Light and dark mode follow the system through the expo-router `ThemeProvider`. Real content arrives once the Rust core is wired in.

## Prerequisites

- Node 22.13+ and npm
- JDK 17 and the Android SDK, with an emulator or a device
- iOS: Xcode for local builds. Otherwise iOS will be built later with the EAS free tier.

## Run the dev build

```sh
npm ci
npm run ubrn:android   # builds core/berean-ffi and generates its bindings (see below)
npx expo run:android   # builds and installs the dev client (npm run android)
npm start              # Metro for the installed dev client (expo start --dev-client)
```

`ios/` and `android/` are generated by Continuous Native Generation (CNG) from `app.json` and config plugins. They are gitignored, so don't edit them by hand.

## Rust core bindings

The app reaches the Rust core through the local TurboModule [`modules/berean-ffi-rn`](modules/berean-ffi-rn/README.md). Its bindings are generated and gitignored, so run `npm run ubrn:android` before typecheck, prebuild, or a native build, and again after `core/` changes. It needs Rust with the Android targets, `cargo-ndk`, and the NDK (`ANDROID_NDK_HOME`). In a dev build, `berean://dev-ffi` prints a plain-text smoke test of the bindings.

## Checks

```sh
npm run typecheck   # tsc --noEmit (strict)
npm run lint        # expo lint (eslint-config-expo)
npx expo-doctor
```

`eas.json` defines only a `development` profile (dev client, internal distribution). No EAS project is linked yet.

## App identifiers

iOS bundle ID and Android package are both `com.odonckers.berean.mobile`. The Apple app already uses `com.odonckers.berean`.
