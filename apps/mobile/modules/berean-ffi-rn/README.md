# berean-ffi-rn

The Berean Rust core (`core/berean-ffi`) as a React Native TurboModule, generated by [uniffi-bindgen-react-native][ubrn] (ubrn), `jsi` flavour. The app depends on it as `"berean-ffi-rn": "file:modules/berean-ffi-rn"`, and Expo autolinks it on `expo prebuild`. Design and rationale: [`docs/design/mobile-bindings.md`](../../../../docs/design/mobile-bindings.md).

## Generate the bindings

From `apps/mobile` (or run the same scripts here):

```sh
npm run ubrn:android    # cargo-ndk build (arm64-v8a, x86_64, release) + generate everything
npm run ubrn:generate   # regenerate everything from the already built library, no cargo
npm run ubrn:ios        # macOS only: xcframework + generate everything
npm run ubrn:clean      # delete everything ubrn generated
```

`ubrn:android` and `ubrn:generate` also create an empty `android/proguard-rules.pro`: the generated `build.gradle` references it, but ubrn only renders it for the `native_bindings` flavour, and `jsi` has no JNA classes to keep.

Run `npm run ubrn:android` before `npx expo prebuild`, `npm run typecheck`, or a native build. Without the bindings, `berean-ffi-rn` has no entrypoint: typecheck fails with `Cannot find module 'berean-ffi-rn'`, and autolinking finds no Android library. Re-run the command whenever `core/` changes.

Android needs the NDK (`ANDROID_NDK_HOME`), `cargo-ndk` 4.1.2, and the Rust targets `aarch64-linux-android` and `x86_64-linux-android`. The first run also compiles the `ubrn` CLI into `node_modules`.

## Configuration

- [`ubrn.config.yaml`](ubrn.config.yaml) points at the core in place (`../../../../core`, crate `berean-ffi/Cargo.toml`). Nothing is checked out or copied.
- Android builds only `arm64-v8a` and `x86_64`. `apiLevel: 24` is passed to cargo-ndk as `--platform`, and must match the app's `minSdk`. React Native 0.88 sets `minSdk = "24"` in `react-native/gradle/libs.versions.toml`.
- The Rust links into the TurboModule's `.so` as a static library, which is ubrn's default. Cargo builds into `core/target/`.
- `package.json` `codegenConfig` names the Codegen spec (`BereanFfiRnSpec`) and the Android package (`com.bereanffirn`), and ubrn derives the generated glue from them.

## What is committed

Only `package.json`, `ubrn.config.yaml`, `.gitignore`, and this README are committed. ubrn regenerates everything else, so it's all gitignored:

| Path | What |
| --- | --- |
| `src/generated/`, `cpp/generated/` | TypeScript and JSI C++ bindings |
| `src/index.tsx`, `src/NativeBereanFfiRn.ts` | Entrypoint and Codegen installer spec |
| `cpp/berean-ffi-rn.{h,cpp}` | TurboModule C++ |
| `android/` | `build.gradle`, `CMakeLists.txt`, `cpp-adapter.cpp`, manifest, Kotlin package, `src/main/jniLibs/*/libberean_ffi.a` |
| `ios/`, `*.podspec`, `build/` | iOS installer, podspec, xcframework |

CI (`.github/workflows/mobile.yml`) runs `npm run ubrn:android`. It then fails if that changed any tracked file or left anything untracked, and finally runs typecheck and lint.

## Using it

```ts
import { Core, CoreError, CancelToken } from 'berean-ffi-rn';
```

- `u64` and `i64` are `bigint`.
- `Catalog.ingestFile` and `Library.install` return `Promise<void>`.
- Match errors with `CoreError.instanceOf(e)` or `e.tag`, never `instanceof`.

`src/ffi/__typetests__/bindings.test-d.ts` in the app pins these shapes at compile time. In a dev build, `berean://dev-ffi` runs a plain-text smoke test (`src/ffi/diagnostics.ts`) and logs its results under the tag `[berean-ffi]`.
